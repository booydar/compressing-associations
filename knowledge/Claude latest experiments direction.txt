  segment tokens (B,T,d)

  That is rank-1 in token-mixing. A convex blend of {!, k1, k2, :, v1, v2, !}

  represent binding at all. You're not bandwidth-limited; you're
  operation-limited.

  What this means

  You actually have three bottlenecks for segment-level recurrent models, not
  one. Naming them cleanly is probably worth a subsection in the paper:

  1. State capacity — state_size × d_v. Standard.
  2. Per-segment write rank — number of independent updates injected into state
  per segment. M=1 means rank 1.
  3. Per-write binding capacity — what a single write update can express about
  structured intra-segment content (does it support k↔v binding, or only
  summarization?).

  Token-level GDN sidesteps (2) and (3) for free: rank=T, and the rank-1
  outer-product GDN update is itself a binder when applied to consecutive (k, v)
   tokens. Identity wins for the same reason.

  Soft-pool with M=1 fails on (3). Soft-pool with M=pps mostly fixes both.
  md=256 only addresses (1). That's why your knob doesn't move.

  M2. Predictive memory writes — MemUP, but for GDN (2022 → 2026)

  Your Explain my surprise notes from Sorokin 2022 are sitting on a really good
  objective that nobody fully exploited. The thing you write to memory should be
   the part of the segment that maximizes mutual information with the future.
  Modern data-dependent gates (β in GDN, A in Mamba) are implicit surprise. Make
   it explicit: train a separate surprise predictor; multiply its output into
  the GDN write gate.

  Your memory and energy note: test-time compute scaling currently means more
  reasoning tokens. What if scaling means more write refinement? Replace the
  single-shot write op with an iterative refinement loop (think Diffusion-Refine
   but on the memory vector): N micro-steps of (read state → propose update →
  score → commit). Stop when the score plateaus. Each segment, the model decides
   how much compute to spend on writing.

  - The flashy claim: compute and memory are dual; you can trade test-time write
   compute for state size. We make the trade explicit and trainable.
  - Bold positioning: unifies CoT-style scaling, fast weights, RNN memory in one
   framework.
  - Risk: training loop is gnarly. But the diagnostic version (just iterate the
